1. 软件介绍

这是一款基于游戏《Fate/Grand Order》中Lancer因陀罗制作的同人桌宠。桌宠无盈利，一切版权归于原版权方。

除了提交给模型api服务商的数据之外，一切用户数据（聊天记录、屏幕截图、从聊天记录中抽取的长期记忆等）存储于本地。想要使用对话功能，你需要自备deepseek、chatgpt或者硅基流动等服务商的api url和key。

2. 初始设置

2.1 原理说明

桌宠的屏幕监视和评论功能基于定时截图和图像识别技术实现。实际我将这个功能拆分成了两块，分别由两个模型处理：

首先是图像识别，桌宠在截图之后将会传给第一个模型api，用于生成图像描述。

目前我使用的识图模型是SiliconFlow的Qwen/Qwen3-VL-32B-Instruct，主要是它好用的同时注册送14块钱的免费额度啊（

当然，生成图像描述的模型使用其他支持图像识别的多模态模型应该也行得通，你可以在设置界面里自由更换。

如果你要去注册硅基流动的话，可以用一下我的邀请链接吗？🙏开发因陀罗桌宠使我的api额度像干冰般蒸发（
邀请链接：https://cloud.siliconflow.cn/i/nkM72iXr
邀请码：nkM72iXr

接下来是评论生成，程序会将图像描述等信息传给第二个模型api，用于生成对当前屏幕内容的评论。所以设置里会有两个填模型api的选项。两个选项填一样的也可以哦。

2.2 api设置

步骤1：注册并获取两个llm api的url和key（见上文原理说明，如果搞不懂怎么获取api的话你可以抓个ai来咨询一下）；

步骤2：启动桌宠，在立绘上右键打开菜单，

打开设置界面，切到“模型设置”选项卡；

步骤3：在设置界面中填写两个模型api的url和key并保存，点击“刷新模型列表”可以从api服务商处拉取可用模型列表，点击“测试连接”测试模型的可用性；

步骤4：双击立绘打开对话框，和因陀罗大人聊两句吧！

3. 基本使用

3.1 拖动桌宠

按住鼠标左键拖动因陀罗桌宠，可自由调整其在屏幕上的位置。

3.2 与桌宠聊天

双击因陀罗桌宠立绘，会弹出聊天框，输入文字后发送，ta会回复消息。

如果回复内容合适，因陀罗会根据语气在立绘右边弹出一个emoji。

3.3 屏幕监视功能

方式1：右键点击托盘图标，选择「屏幕监视：开启/关闭」，实时切换功能；

方式2：打开设置界面，勾选「启用屏幕监视」，设置间隔时间后保存；

功能说明：开启后，因陀罗桌宠会按设定间隔截图，自动评论屏幕内容（需配置API密钥）。

3.4 长期记忆（实验阶段）

右键菜单里可以快速选择长期记忆功能的开启/关闭。

在设置界面中勾选“启用长期记忆”，桌宠会根据聊天记录抽取长期记忆。

其中「附带对话轮数 N」表示：每 N 轮用户聊天结束后，将连续 N 轮一并送记忆录入/整理模型判断和提取；不含屏幕评论；样本不重叠、不遗漏。多批待抽取会按顺序排队执行。

目前长期记忆的抽取标准还有点薛定谔——哪些该记、哪些不该记，主要由记忆专用模型按下面这份 prompt 里的规则来判断。你可以自行打开并修改：

  • 开发版 / 源码运行：项目根目录 config/prompts/memory_extract.md
  • 打包版：安装文件夹内 _internal\config\prompts\memory_extract.md（随程序分发；重装或覆盖安装前请自行备份改过的版本）

修改后需重启桌宠才会生效。抽取走「记忆录入/整理模型」（设置 → 记忆管理页配置），与主聊天模型相互独立；也可在该页点击「测试记忆抽取」先试跑一轮。

4. 设置说明

右键点击托盘图标，选择「设置」，可调整以下选项：

  • 显示缩放：调整立绘大小（0.1-5.0倍）；
  • 聊天框字体大小：调整聊天框字体大小；
  • 空闲后主动行为触发间隔：设置多久无操作后播放待机动画（这个功能还没做）；
  • 屏幕监视：开启/关闭定时截图评论功能；
  • 长期记忆：开启/关闭长期记忆功能；
  • 聊天窗口显示模型思考过程（可折叠）：我记得thinking内容会影响聊天正文的提取所以我对大部分模型关闭了thinking……这个选项大概没什么用
  • 屏幕监视间隔：因陀罗桌宠评论屏幕内容的间隔时长；
  • 临时聊天气泡显示时长：设置桌宠头顶临时消息的显示时间；
  • 桌宠称呼用户为：你希望因陀罗桌宠怎么称呼你？

5. 数据库说明

桌宠里其实有两套互不替代的「记忆/知识」系统，别混为一谈：

  • 剧情库 RAG（lore + style）：给因陀罗补设定与说话风格参考，只读、随安装包分发；
  • 长期记忆库（user_memory.db）：记录关于你的事，开关打开后才写入，存在本地配置目录。

5.1 剧情库（RAG）结构

剧情检索用 LlamaIndex 做向量索引。语料中日文中文都有，嵌入模型为本地离线的 Alibaba-NLP/gte-multilingual-base（约 560MB，目录 models\gte-multilingual-base，已打进安装包）。

源数据与索引位置（开发版路径；打包版在 _internal\ 下同名路径）：

  • src\llm\persona.txt — 因陀罗基础人设与对话 system prompt（不是向量库的一部分，但和 RAG 一起注入聊天）；
  • src\llm\knowledge\style\ — 角色语音/台词脱水文本，聊天时随机抽几条注入，用来微调语气；
  • src\llm\knowledge\lore\ — FGO 与《摩诃婆罗多》等剧情梗概（story_*.txt + 可选 *.facts.json），按用户发言语义检索相关片段；
  • src\llm\knowledge_db\lore\、src\llm\knowledge_db\style\ — 上述语料建好的向量索引（体积较大，发布包内已预构建，首次启动无需联网重建）。

打包用户一般不用自己维护剧情库；若你在源码环境往 knowledge\ 里加了新文件，程序会在后台检测变更并增量更新索引（开发版写入 knowledge_db\）。

5.2 长期记忆库

与剧情库分离，数据在 SQLite 文件 config\user_memory.db（打包版在 exe 同级 config\ 下）。仅在设置里开启「长期记忆」后，后台才会从聊天记录（及屏幕观察描述）里抽取条目写入。

  • 聊天结束后由记忆专用模型异步抽取，不阻塞聊天窗口；
  • 对话时按语义 + 新近度检索相关记忆，注入 system prompt；
  • 可在设置 →「记忆管理」里查看、编辑、置顶、整理或清空。

抽取规则见 config\prompts\memory_extract.md（见上文 3.4 节路径说明）。

5.3 AI 风格与人设微调

不同聊天模型的戏量差很多；作者自用 DeepSeek 官方模型，你换模型后口吻可能差别很大，按喜好选即可。

  • 改人设：编辑 src\llm\persona.txt（打包版：_internal\src\llm\persona.txt）；
  • 改语气样本：编辑 src\llm\knowledge\style\ 下文本（需开发环境或自行重建 style 索引）；
  • 改输出格式/情绪标签等硬编码逻辑：需改源码（如 src\llm\chat_manager.py、src\llm\pipelines\chat_pipeline.py），普通用户不必动。

若 AI 钻牛角尖、反复演绎旧话题，可在设置里把「保留对话轮数」调小，或在记忆管理里整理/删除相关长期记忆条目。

6. 常见问题

Q1：桌宠因陀罗的立绘突然消失了？
A1：我尽量修了这个bug，但至今为止也没太搞懂这个bug的原因，好在还是很好解决的！从系统托盘图标里开右键菜单，点「显示桌宠」就能让它重新出现啦！如果还是不行，先点「隐藏桌宠」再点「显示桌宠」试试。
Q2：屏幕监视功能有时候没反应？
A2：取决于网络状况和模型api的响应速度，截图之后需要一些时间才能生成评论，有时候还会碰到模型api403错误。你可以尝试检查网络状况，或者换一个响应速度更快的模型api。
Q3：功能这么简单为什么程序有3个G那么大啊！
A3：考虑到不是谁都有科学上网的网络条件，为了让人人都能开箱即用，我把模型离线打包到程序里面去了……再加上python依赖库和编译器什么的，最后就……
2026/1/19更新：把模型换成了Alibaba-NLP/gte-multilingual-base，成功把模型占用空间从2GB砍到了560MB，谢谢你阿里达摩院!
