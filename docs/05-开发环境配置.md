# 开发环境配置

本文说明 clone 仓库后如何在本地跑起来，以及如何配置 **不提交 Git** 的 API 密钥。

## 1. 克隆与 Python 环境

```powershell
git clone https://github.com/CheshireClef/Indra_Desktop_Pet.git
cd Indra_Desktop_Pet

python -m venv venv
.\venv\Scripts\activate
pip install PySide6 llama-index-core llama-index-embeddings-huggingface requests mss Pillow transformers torch huggingface_hub python-dotenv
```

依赖详情见 [02-技术要点.md](./02-技术要点.md)。

## 2. 本地嵌入模型

程序启动时会加载 `models/gte-multilingual-base/`。若目录不完整：

```powershell
python src/download_model.py
```

须包含 `config.json`、`modeling.py`、`configuration.py` 及 `.bin` 或 `.safetensors` 权重。

## 3. `.env` 文件（开发专用）

### 为什么需要

- `.gitignore` 已忽略 `.env`、`.env.local`，**密钥不会推到 GitHub**。
- 开发环境（`sys.frozen` 为假）下，`SettingsManager` 会 `load_dotenv` 加载项目根目录的 `.env`。
- **打包后的 exe 不读 `.env`**，最终用户只在设置界面填写，写入 `config/settings.json`。

### 创建步骤

根目录已有模板 `.env.example`：

```powershell
copy .env.example .env
```

用编辑器打开 `.env`，填入真实密钥。完整模板见根目录 `.env.example`。

**两套独立连接（对话 DeepSeek + 识图 SiliconFlow，推荐开发用法）：**

```env
# 方式 A：旧版变量名
LLM_PROVIDER=deepseek
LLM_API_KEY=sk-你的DeepSeek密钥
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat

VISION_API_URL=https://api.siliconflow.cn/v1/chat/completions
VISION_API_KEY=sk-你的SiliconFlow密钥
VISION_MODEL=Qwen/Qwen3-VL-32B-Instruct
```

```env
# 方式 B：新版 MODELS_*（与设置界面字段一一对应）
MODELS_VENDOR=deepseek
MODELS_API_KEY=sk-你的DeepSeek密钥
MODELS_BASE_URL=https://api.deepseek.com
MODELS_CHAT_MODEL=deepseek-chat

MODELS_VISION_VENDOR=siliconflow
MODELS_VISION_API_KEY=sk-你的SiliconFlow密钥
MODELS_VISION_BASE_URL=https://api.siliconflow.cn/v1
MODELS_VISION_MODEL=Qwen/Qwen3-VL-32B-Instruct
# MODELS_SAME_CONNECTION_AS_CHAT=false   # 可选；不填时 Key/URL 不同会自动独立
```

**共用同一 API 时**只需填对话侧 `MODELS_VENDOR` / `MODELS_API_KEY` / `MODELS_BASE_URL` / `MODELS_CHAT_MODEL`，再加 `MODELS_VISION_MODEL` 即可。

设置界面「模型设置」页：**对话模型**与**屏幕识图模型**各有一套 API 连接（服务商 / Base URL / Key）。识图默认勾选「与上方使用同一 API 连接」，此时识图侧 API 与对话一致且灰显；取消勾选后可单独配置识图 API。流程：填 API → **刷新模型列表** → 选模型 → **测试识图** 后再开屏幕监视。

### 优先级

开发环境下 `get_chat_binding()` / `get_vision_binding()` 及 `SettingsManager.get("llm", "api_key")` 等：

1. `.env` 中对应环境变量（非空，仅注入内存，**不落盘** `settings.json`）
2. `config/settings.json` 中的 `models` 块
3. 代码默认值

因此本地测试时只需维护 `.env`，不必把密钥写进 `settings.json`。

### 验证是否加载成功

启动程序时控制台应出现：

```
[SettingsManager] 开发环境：已从 D:\...\Indra_Desktop_Pet\.env 加载 .env 配置
```

若显示「未找到 .env 文件」，请确认文件在项目根目录且名为 `.env`（不是 `.env.txt`）。

## 4. `config/settings.json`

首次运行会自动生成。可配置非敏感项，例如：

- 桌宠缩放、用户称呼
- 屏幕监视开关与间隔（`behavior.screen_watch_enabled`）
- 长期记忆开关（`behavior.long_term_memory_enabled`）
- LLM `temperature`、`history_rounds` 等（未被 `.env` 映射的字段）

当前仓库中的 `settings.json` 可能含个人偏好；**不要**在其中提交 API Key。

## 5. 启动与功能验证

```powershell
python src/main.py
```

建议验证：

| 步骤 | 预期 |
|------|------|
| 双击立绘打开聊天 | 发送消息后收到因陀罗口吻回复 |
| 托盘 → 设置 → 模型 | 开发环境下 Key 可留空（已由 .env 提供） |
| 开启屏幕监视 + 配置视觉 Key | 间隔到达后出现临时评论气泡 |
| 开启长期记忆 | 对话中提及偏好后，可在「记忆管理」看到条目 |

## 6. 安全提醒

- **切勿** `git add .env` 或提交含真实 Key 的 `settings.json`。
- 若误提交密钥，应轮换 API Key 并从 Git 历史中清除（需 force 操作，谨慎处理）。
- 协作者各自维护本地 `.env`，共享配置只通过 `.env.example` 模板。
