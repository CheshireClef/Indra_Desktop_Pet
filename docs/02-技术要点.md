# 技术要点

本文档汇总运行环境、核心依赖、外部 API 与本地资源，便于环境复现。项目当前**未**提供 `requirements.txt`，依赖以本文档与历史提交中的 `requirements.txt` 记录为准。

## 1. 运行环境

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 / 11 |

## 3. 外部 API

### 3.1 模型接入层（`ModelService` + `OpenAICompatibleClient`）

- **配置真相源**：`settings.json` → `models`（v2）；`llm`/`vision` 为读写兼容投影
- **Vendor 注册表**：`src/llm/providers/registry.json`（预置 base_url，不硬编码 model id）
- **动态模型列表**：`GET {base_url}/v1/models`（设置页「刷新模型列表」）
- **能力探测**：测试连接 / 测试识图 → 写入 `capabilities_cache`

### 3.2 LLM（聊天 + 屏幕评论文案）

- **协议**：OpenAI 兼容 Chat Completions（`llm/clients/openai_compatible.py`）
- **JSON 输出策略**（`output_mode=auto`）：`response_format` → 仅 Prompt JSON → 自然语言 + 情绪标签解析
- **配置**：`models.chat.*`；`output_mode`：`auto` | `json_preferred` | `natural_only`
- **推荐服务商**：DeepSeek、硅基流动、OpenRouter、MiniMax 等（见 registry）

### 3.3 视觉 API（截图 → 文字描述）

- **协议**：同一 OpenAI 兼容客户端的多模态 `image_url` 请求（`llm/clients/vision_request.py` 统一构造）
- **配置**：`models.vision.model`；可与对话共用 `models.connections[0]`
- **推荐**：`Qwen/Qwen3-VL-32B-Instruct` 等 VL 模型；设置页「测试识图」验证
- **自适应探测**（`llm/clients/vision_adapter.py`）：探测图 32/64/128px（非 1×1，兼容 GLM-VL 最小边长）；按 `registry.json` 的 `vision_defaults` + 模型族启发 + 自动重试（尺寸/思考链/图文顺序）；成功参数写入 `capabilities_cache.vision_hints`，正式识图复用
- **SiliconFlow 等**：结构化路径（识图/记忆/JSON 探测）经 `reasoning_extras.py` 合并 `registry.json` 的 `reasoning_defaults` 与模型族启发（Qwen `enable_thinking` + `chat_template_kwargs`、OpenAI `reasoning_effort`、OpenRouter `reasoning.effort`、Ollama `think` 等）；解析走 `extract_vision_message_content`

### 3.4 长期记忆录入 / 整理 API

- **配置**：`models.memory`（`same_connection_as_chat`、`model`、`temperature`、`max_tokens`、`extract_context_rounds`）；独立连接 id 为 `memory`
- **聊天抽取**：`MemoryExtractWorker` 在 `chat_with_tag` 成功 append assistant 后启动；规则见 `config/prompts/memory_extract.md`
- **触发**：仅当聊天 JSON **解析成功**且已写入 history 后调度；解析失败（残缺 JSON/幻觉）不 append、不抽取。`extract_context_rounds = N`：N=1 每轮；N>1 每 N 轮一次。跳过时终端有 `[MemoryExtract] 本轮跳过`
- **JSON**：记忆模型使用 `json_only_policy` + `capabilities_cache.json_mode`；请求附带 `reasoning_payload_extras(profile=structured)`，正文解析失败时回退 `extract_vision_message_content`
- **主聊天 JSON**：schema 仅 `reply` + `emotion`；解析见 `llm/parsers/chat_response.py`。残缺 JSON 不回退全文；失败重试 1 次，仍失败则红气泡且不写 history。`llm.max_reply_chars`（默认 800）
- **DeepSeek 聊天**：因 [官方 JSON Output 可能返回空 content](https://api-docs.deepseek.com/zh-cn/guides/json_mode)，`deepseek*` / `api.deepseek.com` 强制 `natural_only`（正文 + 末尾【情绪】），不走 `response_format`；记忆抽取仍用 memory 模型 JSON
- **主聊天思考链**：`parse_chat_completion()` → `LLMChatResult`；思考链可折叠展示（`behavior.show_reasoning_in_chat`）
- **探测**：设置页「**测试记忆抽取**」走 `MemoryCapabilityProbeWorker`（JSON 能力 + 与正式抽取相同的试运行），**不**跑识图探测，避免终端误报「识图探测成功」
- **失败**：抽取 API 空响应时最多重试 2 次；终端区分「无有效响应」「已响应但 memories 为空」「解析失败」
- **整理合并**：`long_term_memory._merge_cluster` 与聊天抽取共用记忆模型 API（非对话模型）
- **Token**：每次抽取都会发送完整 system prompt（正常）；可通过增大 N 降低调用频率

## 4. 配置与密钥管理

| 场景 | 配置来源 |
|------|----------|
| **开发环境**（未 PyInstaller 打包） | 项目根目录 `.env` **优先**覆盖 `settings.json` 中的 API 相关字段 |
| **打包发布** | 仅 `config/settings.json`，用户在设置界面填写 |

`.env` 与 `.env.local` 已写入 `.gitignore`，**不会同步到 GitHub**。模板见根目录 `.env.example`。

环境变量映射（见 `src/settings_manager.py`）：

| 环境变量 | 对应 settings 路径 |
|----------|-------------------|
| `LLM_PROVIDER` | `llm.provider` |
| `LLM_API_KEY` | `llm.api_key` |
| `LLM_BASE_URL` | `llm.base_url` |
| `LLM_MODEL` | `llm.model` |
| `VISION_API_URL` | `vision.api_url` |
| `VISION_API_KEY` | `vision.api_key` |
| `VISION_MODEL` | `vision.model` |
| `MODELS_VENDOR` | 对话连接 `connections.default.vendor` |
| `MODELS_API_KEY` | 对话连接 `api_key` |
| `MODELS_BASE_URL` | 对话连接 `base_url` |
| `MODELS_CHAT_MODEL` | `models.chat.model` |
| `MODELS_VISION_VENDOR` | 识图连接 `connections.vision.vendor`（独立连接时） |
| `MODELS_VISION_API_KEY` | 识图连接 `api_key` |
| `MODELS_VISION_BASE_URL` | 识图连接 `base_url` |
| `MODELS_VISION_MODEL` | `models.vision.model` |
| `MODELS_SAME_CONNECTION_AS_CHAT` | 识图是否共用对话连接 |
| `MODELS_MEMORY_VENDOR` | 记忆连接 `connections.memory.vendor`（独立时） |
| `MODELS_MEMORY_API_KEY` | 记忆连接 `api_key` |
| `MODELS_MEMORY_BASE_URL` | 记忆连接 `base_url` |
| `MODELS_MEMORY_MODEL` | `models.memory.model` |
| `MODELS_MEMORY_SAME_CONNECTION_AS_CHAT` | 记忆是否共用对话连接 |
| `MEMORY_API_URL` | 同 `MODELS_MEMORY_BASE_URL`（方式 A 简写） |
| `MEMORY_API_KEY` | 同 `MODELS_MEMORY_API_KEY` |
| `MEMORY_MODEL` | 同 `MODELS_MEMORY_MODEL` |

开发环境下 `get_chat_binding()` / `get_vision_binding()` / `get_memory_binding()` 每次读取前会将上述变量注入内存中的 `models` 块。旧版 `LLM_*` / `VISION_*` / `MEMORY_*` 仍兼容。

**保存时脱敏**：开发环境中，若某连接的 API Key 已由 `.env` 提供，`save()` 写入 `settings.json` 时会把对应 `api_key` 置空，避免在设置页点保存后把密钥落盘并误提交 Git。

非敏感项（如 `temperature`、`screen_watch_interval_s`）仍只从 `settings.json` 读取。

## 6. 离线与安全策略

- 知识库嵌入阶段设置 `TRANSFORMERS_OFFLINE=1` 等，禁止 HuggingFace 联网。
- 聊天内容与截图默认仅存本地；仅用户配置的 API 会外传。
- 向量索引大文件部分已在 `.gitignore` 中排除（如 `default__vector_store.json`），clone 后若缺失需本地重建索引。

## 7. 打包

- 使用 **PyInstaller**，规格文件：`FGO因陀罗桌宠.spec`；一键脚本：根目录 `打包.bat`（使用 `venv`，打包前后自动校验资源）
- **只读资源**（立绘、`models/`、预构建 `knowledge_db`、`persona` 等）经 `utils.resource_path()` → 打包后位于 `_internal`
- **可写用户数据**（`config/settings.json`、`user_memory.db`、`screenshots/`）经 `utils.user_data_path()` → 打包后位于 **exe 同级目录**，首次运行从包内复制默认 `settings.json`
- 分发时须打包整个 `dist/FGO因陀罗桌宠/` 文件夹（含 `_internal`），勿只复制 exe
